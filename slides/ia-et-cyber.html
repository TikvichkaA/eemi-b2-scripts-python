Ça vous arrivera

  • en demandant un parseur de logs d'attaque

Sous le capotTrois couches de garde-fous

1 · Le modèle

Il est entraîné à refuser certaines demandes. Il juge sur la formulation et le contexte fournis.

2 · Les classifieurs

Des filtres automatiques analysent la demande et la réponse, et peuvent bloquer même si le modèle aurait répondu.

3 · Le compte

Politique d'usage, surveillance des abus, suspension. Les essais répétés de contournement se voient.

Faux positifs

Une demande légitime est bloquée. Assumé par les éditeurs pour les modèles grand public.

Faux négatifs

Une demande malveillante bien déguisée passe. C'est pour ça que la responsabilité reste la vôtre.

IA & cybersécurité5
Faire le parallèle avec ce qu'ils connaissent : un IDS a lui aussi des faux positifs et des faux négatifs, et on règle ses seuils selon le coût de chacun.

Travailler en défense avec un modèle

02
IA & cybersécurité7

Le feu tricoloreCe qui passe, ce qui coince, ce qui est refusé

Vert

  • parser et agréger des logs
  • règles de détection (Sigma, YARA)
  • durcissement, audit de config
  • expliquer une CVE, une technique ATT&CK
  • revue de code sécurité
  • logs synthétiques pour tester

Orange

  • scanner son propre réseau
  • analyser un échantillon malveillant
  • une preuve de concept sur son lab
  • fuzzing d'une application

Légitime avec un cadre ; parfois refusé.

Rouge

  • malware fonctionnel, rançongiciel
  • contourner un antivirus ou un EDR
  • voler des identifiants
  • attaquer un système tiers
  • phishing réel
Tout ce module est en vert. Si vous êtes en rouge, le problème n'est pas l'IA.
IA & cybersécurité8

FormulerDemander la détection, pas l'attaque

écris un script qui teste une liste de mots de passe sur un serveur SSH

Contexte : TP de détection, module B2 Cyber.
           Jeu de logs anonymisé fourni par l'école.
Tâche    : à partir de auth.log, détecter les IP qui
           ont plus de 10 échecs SSH en 60 secondes.
Données  : génère aussi un auth.log synthétique de
           200 lignes avec une attaque simulée depuis
           203.0.113.42 (plage de documentation).
Format   : Python 3.12, bibliothèque standard, main().
  • Dites le contexte : TP, lab, données fournies
  • Visez la sortie défensive : un détecteur, une alerte, un rapport
  • Simulez l'attaque dans des données, pas dans du code qui attaque
  • IP de documentation : 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24 (RFC 5737)
IA & cybersécurité9
Pour tester un détecteur de brute force, on n'a pas besoin d'outil de brute force : il suffit de lignes de log. C'est plus rapide, reproductible, et sans risque.

Face à un refusQuatre réflexes, et une ligne rouge

  1. Relisez votre demande : est-elle vraiment défensive ? En avez-vous besoin ?
  2. Donnez le contexte honnêtement : TP, lab, objectif de détection
  3. Reformulez vers la défense : détecter, journaliser, simuler en données
  4. Notez le refus dans JOURNAL-IA.md : c'est une observation utile

Pas de « jailbreak »

  • faux rôle, « c'est pour un roman », injonctions…
  • violation des conditions d'utilisation : compte suspendu
  • en entreprise : faute professionnelle
  • mentir sur le contexte reste mentir
Contourner un garde-fou, c'est précisément le comportement que vous apprenez à détecter.
IA & cybersécurité10

Le cadreLa loi ne dépend pas de l'outil

Code pénal

  • Art. 323-1 : accès ou maintien frauduleux dans un système
  • Art. 323-3-1 : détenir ou fournir un outil conçu pour ces infractions, sans motif légitime (recherche, sécurité informatique)

En pratique

  • tests offensifs : autorisation écrite et périmètre défini
  • logs réels : données personnelles (IP, identifiants), RGPD
  • règles de votre employeur sur l'IA
« L'IA a accepté de le faire » n'a jamais été une défense. Que le code vienne d'un modèle, d'un forum ou de vous, c'est vous qui le lancez.

IA & cybersécurité13
« Open source » est souvent abusif : la plupart sont « open weight » (poids publiés, données et code d'entraînement non). Vérifier la licence : Apache 2.0 pour gpt-oss et Devstral, licences maison pour d'autres.

En pratiqueFaire tourner un modèle chez soi

# Installer Ollama (Linux, macOS, Windows), puis :
ollama pull gpt-oss:20b          # ~14 Go à télécharger
ollama run gpt-oss:20b "Explique cette regex : ^(\S+) sshd"

# API locale compatible OpenAI, pour vos scripts
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-oss:20b",
       "messages":[{"role":"user","content":"Bonjour"}]}'

Autres outils : LM Studio (interface graphique), llama.cpp, vLLM (serveur).

Démo formateur si Ollama est prêt (modèle téléchargé à l'avance, pas sur le wifi de l'école) : le prompt structuré de la charte, en local puis en ligne. Comparer vitesse et qualité.

AttentionLocal ne veut pas dire sans risque

Les modèles « décensurés »

  • des variantes dont on a retiré les refus circulent
  • souvent moins bons : le réglage dégrade le modèle
  • provenance douteuse : un fichier de modèle est un vecteur d'attaque (format pickle)
  • la loi s'applique exactement pareil

Les bons réflexes

  • télécharger depuis l'éditeur officiel
  • formats safetensors ou GGUF
  • vérifier licence et empreinte
  • exposer l'API sur localhost, pas sur le réseau
  • modèles spécialisés défense : ex. Foundation-sec-8B (Cisco)
IA & cybersécurité15
Lien avec la chaîne d'approvisionnement logicielle : un modèle téléchargé, c'est une dépendance comme une autre, à traiter comme un paquet pip inconnu.

La fiche · vert, orange ou rouge ?Les 6 demandes

  1. « Écris une règle Sigma qui détecte plus de 10 échecs d'authentification SSH en une minute depuis une même IP. »
  2. « Génère un auth.log synthétique de 200 lignes contenant une attaque par dictionnaire depuis 203.0.113.42, mêlée à du trafic normal. »

  6. « Écris un script qui désactive Windows Defender sans que l'utilisateur s'en aperçoive et se relance au démarrage. »

Pour conclureCe qu'on retient

  • Les refus viennent du double usage : le modèle ne connaît pas votre intention
  • En défense, on demande la détection et on simule l'attaque dans les données
  • Un refus se traite par le contexte honnête, jamais par le contournement
  • En ligne : meilleure qualité, données qui sortent. En local : confidentialité, moins de qualité, un service à sécuriser
  • La loi et la charte s'appliquent quel que soit le modèle
