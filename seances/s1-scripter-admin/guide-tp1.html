TP1 · Inventaire système

Vous arrivez dans une équipe d'exploitation qui gère une vingtaine de serveurs Linux. Avant chaque intervention, un collègue tape une dizaine de commandes pour faire « l'état des lieux ». Vous allez automatiser cet état des lieux, d'abord en Bash, puis en Python, pour comparer les deux approches.

≈ 95 min Individuel Non noté, mais vérifié IA autorisée, selon la charte
Comment utiliser ce guide

Chaque étape correspond à un TODO des fichiers inventaire.sh et inventaire.py. Lisez l'objectif, essayez seul, puis dépliez les indices un par un si vous bloquez. Cochez l'étape quand elle marche : votre progression est gardée dans ce navigateur.

La référence complète (sorties attendues, options, codes retour) reste le README du TP.

Avant de toucher au code

Ouvrez inventaire.sh et lisez-le en entier : l'en-tête, set -euo pipefail, les fonctions die et titre, et main. Le squelette fait déjà la moitié du travail (lecture des options, écriture dans un fichier). Vous n'avez qu'à remplir les fonctions.

A · En Bash ≈ 40 min

Fichier : inventaire.sh. Testez après chaque étape avec ./inventaire.sh, sans attendre la fin.

Le piège n°1 de ce squelette : IFS=$'\n\t'

Le script ne découpe pas sur les espaces (c'est voulu : ça protège des noms de fichiers avec espaces). Conséquence : read a b < fichier met toute la ligne dans a. Pour découper des colonnes séparées par des espaces, utilisez awk, cut -d' ', ou IFS=' ' read -r … pour cette seule commande.

A1

Compléter l'aide

Objectif. ./inventaire.sh -h affiche l'usage, les trois options (-s, -o, -h) et la signification des codes retour 0, 1 et 2.

Indice 1

Pour afficher plusieurs lignes d'un coup, un here-document est plus lisible qu'une suite d'echo : cat <<EOF … EOF. Les variables comme ${SCRIPT_NAME} y sont remplacées.

Vérifier
./inventaire.sh -h; echo "code retour : $?"    # doit afficher 0
A2

Section « Hôte »

Objectif. Afficher le nom d'hôte, le système, le noyau et l'uptime au format 12j 3h 41min.

== Hôte ==
Nom      : srv-web-01
Système  : Ubuntu 24.04.1 LTS
Noyau    : 6.8.0-45-generic
Uptime   : 12j 3h 41min
Indice 1 · les sources
  • nom : hostname ; noyau : uname -r
  • système : la ligne PRETTY_NAME= de /etc/os-release, sans les guillemets
  • uptime : le premier nombre de /proc/uptime, en secondes (avec des décimales)
Indice 2 · extraire et calculer

Pour le système : grep la ligne, puis cut -d= -f2 et tr -d '"'.

Pour l'uptime, récupérez un entier avec awk '{print int($1)}' /proc/uptime (voir le piège IFS plus haut), puis l'arithmétique Bash : $(( s / 86400 )) donne les jours, $(( s % 86400 / 3600 )) les heures. À vous les minutes.

Pour aligner : printf '%-9s: %s\n' "Nom" "$(hostname)".

A3

Section « CPU et mémoire »

Objectif. Nombre de cœurs, charge moyenne (1, 5 et 15 min), mémoire disponible et totale en Mio.

Indice 1
  • nproc donne le nombre de cœurs.
  • Les trois premiers champs de /proc/loadavg sont la charge : cut -d' ' -f1-3.
  • Dans /proc/meminfo, les lignes MemTotal et MemAvailable sont en kio. Divisez par 1024.
Indice 2 · un seul awk pour la mémoire
awk '/^MemTotal:/ {t=$2} /^MemAvailable:/ {a=$2}
     END {printf "%d Mio disponibles sur %d Mio\n", a/1024, t/1024}' /proc/meminfo

Pourquoi MemAvailable et pas MemFree ? Cherchez la différence dans man proc.

A4

Section « Disques » et alerte

Objectif. Pour chaque système de fichiers réel : point de montage et % d'occupation. Si le % est supérieur ou égal au seuil, ajouter ALERTE et passer ALERTE=1 : c'est ce qui donnera le code retour 1.

== Disques (seuil 80 %) ==
/                          47 %
/var                       86 %  ALERTE
Indice 1 · la source

df -P -x tmpfs -x devtmpfs : -P garantit une ligne par système de fichiers (format POSIX), -x exclut les types virtuels. tail -n +2 retire la ligne d'en-tête. Le % est en 5e colonne, le point de montage en 6e.

Indice 2 · la boucle
while IFS=' ' read -r _ _ _ _ pct point; do
    pct="${pct%\%}"          # retire le signe %
    # à vous : printf aligné, comparaison avec (( pct >= SEUIL )), ALERTE=1
done < <(df -P -x tmpfs -x devtmpfs | tail -n +2)
Piège · « ALERTE reste à 0 alors que le disque est plein »

Si vous écrivez df … | while read …, la boucle tourne dans un sous-shell : la variable ALERTE modifiée dedans est perdue à la sortie. D'où la forme done < <(cmd) ci-dessus. C'est la question de synthèse n°4.

Autre piège : (( ALERTE++ )) quand ALERTE vaut 0 renvoie un code d'échec, et set -e arrête le script. Écrivez simplement ALERTE=1.

Vérifier
./inventaire.sh -s 0;   echo "code : $?"   # tout en ALERTE, code 1
./inventaire.sh -s 100; echo "code : $?"   # aucune alerte, code 0
A5

Section « Comptes interactifs »

Objectif. Lister les comptes humains : UID ≥ 1000, sauf 65534 (nobody), et dont le shell ne finit ni par nologin ni par false.

Indice 1

/etc/passwd a 7 champs séparés par :. Le champ 1 est le nom, le 3 l'UID, le 7 le shell. awk -F: découpe sur les deux-points.

Indice 2

Une condition awk se place avant le bloc : awk -F: 'CONDITION {printf …}' /etc/passwd. Il vous faut trois conditions reliées par &&, dont une sur le shell avec $7 !~ /(nologin|false)$/.

Si la liste est vide

Dans un conteneur, il n'y a souvent aucun compte humain. Créez-en un pour tester : sudo useradd -m -s /bin/bash test01, puis supprimez-le après.

A6

Section « Ports TCP en écoute »

Objectif. Lister les adresse:port TCP en écoute, sans doublon. Si ss n'existe pas, afficher « non disponible » et continuer.

Indice 1

command -v ss >/dev/null réussit si la commande existe. C'est la bonne façon de tester, pas which.

Indice 2

ss -Htln : -H sans en-tête, -t TCP, -l en écoute, -n sans résolution de noms. L'adresse locale est en 4e colonne. Terminez par sort -u.

Vérifier le cas « ss absent »

Le plus simple : un conteneur minimal, où ss n'est pas installé.

docker run --rm -v "$PWD":/tp -w /tp debian:stable-slim bash inventaire.sh -s 100

Sans Docker : remplacez un instant ss par ss_absent dans votre test command -v, vérifiez que « non disponible » s'affiche, puis remettez ss.

A7

Refuser un seuil invalide

Objectif. -s abc, -s -5 ou -s 150 doivent donner un message d'erreur sur stderr et le code retour 2.

Indice 1

Deux tests : que ce soit un entier (expression régulière avec [[ … =~ … ]]), puis qu'il soit ≤ 100. Dans cet ordre : (( )) sur une chaîne non numérique donne des résultats surprenants.

Indice 2

La fonction die existe déjà : elle écrit sur stderr et sort avec le code 2. Le motif d'un entier positif : ^[0-9]+$.

Fin de la partie A

bash verifier_tp1.sh : les 10 premières lignes (partie A) doivent être [OK]. Si shellcheck est installé, il doit aussi être satisfait. Faites un commit : git add inventaire.sh && git commit -m "TP1 partie A".

B · En Python ≈ 45 min

Fichier : inventaire.py. Même inventaire, avec en plus une sortie JSON, des messages de diagnostic sur stderr et des erreurs propres. Bibliothèque standard uniquement.

Ordre conseillé

Faites d'abord les arguments (B9) et main() (B10) avec la sortie JSON : vous pourrez alors tester chaque fonction de collecte dès qu'elle est écrite. La sortie texte (B8) vient en dernier. Pour tester une seule fonction :

python3 -c "import inventaire; print(inventaire.lire_meminfo())"
B9

Les arguments

Objectif. -s/--seuil (entier de 0 à 100, défaut 80), -f/--format (texte ou json), -o/--output (fichier), -v/--verbose.

Indice 1

p.add_argument("-f", "--format", choices=["texte", "json"], default="texte"). Pour -v, cherchez action="store_true" dans la doc d'argparse.

Indice 2 · valider le seuil

Le paramètre type= accepte n'importe quelle fonction. Si elle lève argparse.ArgumentTypeError, argparse affiche le message et sort avec le code 2, tout seul.

def pourcentage(valeur: str) -> int:
    # convertir en int, vérifier 0..100, sinon raise argparse.ArgumentTypeError("…")
B10

Le programme principal

Objectif. Collecter, formater selon --format, écrire sur stdout ou dans --output, et renvoyer 0, 1 ou 2.

Indice 1 · les étapes
  1. si args.verbose, passer le logger en DEBUG ;
  2. inv = collecter(args.seuil) ;
  3. JSON : json.dumps(inv, ensure_ascii=False, indent=2), sinon formater_texte(…) ;
  4. écrire : print(…) ou Path(args.output).write_text(…, encoding="utf-8") ;
  5. renvoyer EXIT_ALERTE si inv["alerte"], sinon EXIT_OK.
Indice 2 · une erreur propre, pas une trace

Écrire dans /dossier/inexistant/x.json lève une OSError (ou une sous-classe). Attrapez-la autour de l'écriture, log.error("…: %s", e), puis return EXIT_ERREUR.

Pourquoi logging et jamais print pour les messages ? Essayez python3 inventaire.py -f json | python3 -m json.tool avec un print("debug") qui traîne.

B1

lire_os_release()

Objectif. Renvoyer la valeur de PRETTY_NAME sans guillemets, ou "inconnu" si le fichier est absent ou ne la contient pas.

Indice 1

chemin.read_text().splitlines(), puis cherchez la ligne qui commence par PRETTY_NAME=. str.partition("=") et str.strip('"') font le reste.

Indice 2

Le fichier absent lève FileNotFoundError : attrapez OSError pour couvrir aussi les droits. Le paramètre chemin sert aux tests : on pourra lui passer un faux fichier en séance 5.

B2

infos_hote()

Objectif. {"nom", "systeme", "noyau", "uptime_s"}.

Indice

Tout est dans le commentaire du TODO. Pour l'uptime : premier champ de /proc/uptime, converti en float puis en int.

B3

infos_cpu()

Objectif. {"coeurs": int, "charge": [float, float, float]}.

Indice

os.getloadavg() renvoie un tuple : le JSON attendu est une liste, avec des valeurs arrondies à 2 décimales (round(x, 2)).

B4

lire_meminfo()

Objectif. {"total_mio": int, "disponible_mio": int} à partir de MemTotal et MemAvailable.

Indice

Une ligne ressemble à MemTotal: 8127920 kB. ligne.split() donne ['MemTotal:', '8127920', 'kB']. Construisez un dictionnaire clé → valeur, puis divisez par 1024 avec // pour garder un entier.

B5

infos_disques()

Objectif. Une entrée par système de fichiers réel, avec le même % que df (le vérificateur tolère 1 point d'écart). Un montage inaccessible ne doit pas faire planter le script.

Indice 1 · la boucle
  • chaque ligne de /proc/mounts : périphérique, point de montage, type, … ;
  • sauter les types de FS_IGNORES et les points déjà vus (un même point peut apparaître deux fois) ;
  • shutil.disk_usage(point) dans un try / except OSError, avec un log.debug si ça échoue.
Indice 2 · le bon pourcentage

disk_usage renvoie total, used et free. Si vous calculez used / total, vous serez à côté de df. df calcule used / (used + free) et arrondit au supérieur (math.ceil). Pourquoi ? C'est la question de synthèse n°3.

Piège · les points de montage avec espaces

Dans /proc/mounts, un espace est écrit \040. Rare sur un serveur, mais un script robuste le gère : point.replace("\\040", " ").

B6

lire_comptes()

Objectif. Même règle qu'en A5, en Python.

Indice

champs = ligne.split(":") ; l'UID est int(champs[2]), le shell champs[6]. shell.endswith(("nologin", "false")) accepte un tuple. Ignorez les lignes vides ou mal formées plutôt que de planter.

B7

ports_tcp_ecoute()

Objectif. Liste triée et sans doublon des adresse:port, ou None si ss est absent ou échoue.

Indice 1

L'appel est donné dans le TODO. Passez la commande en liste (["ss", "-Htln"]), jamais en chaîne avec shell=True.

Indice 2 · les trois erreurs
  • FileNotFoundError : la commande n'existe pas ;
  • subprocess.CalledProcessError : elle a renvoyé un code ≠ 0 (à cause de check=True) ;
  • subprocess.TimeoutExpired : elle a dépassé 5 s.

Dans les trois cas : un log.warning et return None. Puis sorted({ligne.split()[3] for ligne in …}).

B8

formater_texte()

Objectif. Reproduire exactement la présentation de inventaire.sh à partir du dictionnaire inv.

Indice

Construisez une liste de lignes, puis "\n".join(lignes). L'alignement se fait dans les f-strings : f"{'Nom':<9}: {h['nom']}", f"{d['point_montage']:<26} {d['utilise_pct']:>2} %". Pensez au cas ports_tcp is None → « non disponible ».

Vérifier
diff <(./inventaire.sh -s 100 | tail -n +2) <(python3 inventaire.py -s 100 | tail -n +2)

Les deux sorties doivent être identiques (on retire la ligne de date). L'uptime peut différer d'une minute.

Fin de la partie B

bash verifier_tp1.sh doit afficher 21 OK (20 si shellcheck n'est pas installé). Commit : git commit -am "TP1 partie B".

C · Avec l'IA pendant tout le TP

C

Deux entrées dans JOURNAL-IA.md

  1. Choisissez une fonction de la partie B (par exemple infos_disques ou ports_tcp_ecoute) et faites-la écrire par l'IA de votre choix.
  2. Utilisez un prompt structuré, comme dans la charte. Point de départ :
Contexte    : Ubuntu 24.04, Python 3.12, bibliothèque standard uniquement.
Tâche       : écrire la fonction infos_disques(seuil, mounts) qui lit /proc/mounts
              et renvoie une liste de dictionnaires (voir la docstring ci-dessous).
Contraintes : ignorer les FS virtuels ; un montage inaccessible ne fait pas planter ;
              le % doit être identique à celui de df.
Format      : la fonction seule, avec annotations de type.
Demande     : explique ton calcul du pourcentage, puis propose 2 cas de test.
# + collez la signature et la docstring du squelette
  1. Passez la réponse au crible des 5 questions : je comprends chaque ligne ? entrée absente ou malformée ? effets de bord ? les fonctions existent-elles ? comment je teste ?
  2. Notez dans le journal : le prompt, ce qui n'allait pas, ce que vous avez corrigé, comment vous l'avez vérifié.
  3. Deuxième entrée au choix : l'explication d'une commande, d'une erreur ou d'une regex.
Règle 1 de la charte

Ne collez pas la sortie de votre inventaire si vous travaillez sur une machine de votre entreprise : noms d'hôtes, comptes et ports réels sont des données sensibles.

Questions de synthèse

Dans un fichier reponses.md, dans le dossier du TP. Quelques lignes par question suffisent : on cherche votre raisonnement, pas une définition recopiée.

  1. Citez deux choses plus simples en Bash et deux choses plus simples en Python, d'après votre expérience du TP.
  2. Pourquoi le script doit-il renvoyer 1 quand un disque dépasse le seuil ? Qui va lire ce code retour ?
  3. Votre % en Python est-il le même que celui de df ? S'il diffère, pourquoi ? (Indice : blocs réservés à root.)
  4. Votre script Bash contient-il un cmd | while read ? Quel problème cela pose-t-il pour ALERTE ?
  5. Qu'est-ce que l'IA a fait de travers dans votre partie C ? Comment l'auriez-vous détecté sans exécuter le code ?
